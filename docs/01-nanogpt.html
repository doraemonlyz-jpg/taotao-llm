1 · 为什么先写 nanoGPT

HuggingFace 一行 AutoModelForCausalLM.from_pretrained("gpt2") 你就能跑 GPT。 但你不知道它在做什么。面试官问你 "解释一下 attention" · 你只会说 "Q 乘 K 转置"。 这一本的目的就是让你能从空文件开始 · 写到 generate() 出语言模型样本。

读完你能

① 在白板上画出一个 transformer block 的 forward 图 · ② 解释为什么 attention 里要除 √dₖ · ③ 看懂 nanoGPT / Llama / Mistral 的源码 · ④ 在自己的 Mac 上跑通从训练到采样的整条链路 · ⑤ 知道 phase 2-9 接下来要补什么。

不学这一节会怎样

你会变成 "HuggingFace API 调用员"。能 fine-tune · 但调不动深层问题：模型不收敛 / loss spike / OOM / 推理慢。 这些问题的根都在 transformer 内部 · 你必须看过它的肚子。

2 · 自回归语言建模 · 最小目标函数

"语言模型" 听起来神秘。它的数学表达只有一行：

\[ p(x_1, x_2, \ldots, x_T) = \prod_{t=1}^{T} p(x_t \mid x_1, x_2, \ldots, x_{t-1}) \]

人话

一段文字的概率 = 每个 token 给定前面所有 token 的条件概率之乘积。

训练时 · 我们最小化负对数似然（neg-log-likelihood）：

\[ \mathcal{L} = -\frac{1}{T} \sum_{t=1}^{T} \log p_\theta(x_t \mid x_{

这正好就是 PyTorch 里的 cross_entropy。看 nano/gpt.py 第 forward() 末尾：

loss = F.cross_entropy(
    logits.view(-1, logits.size(-1)),  # (B·T, vocab)
    targets.view(-1),                  # (B·T,)
    ignore_index=-1,
)

"autoregressive" 的字面意思就是 "用过去预测下一个"。模型不能看 t+1 · 这个 "不能看" 是靠 causal mask 强制的（见第 5 节）。

训练数据长什么样

我们把 1MB 莎士比亚整本切成 65 个唯一字符的 id 流。每次随机抽一个长度 256 的窗口当 input · 把它向左平移一位当 target：

input  = "ROMEO: But, soft! what light through yonder window break"
target = "OMEO: But, soft! what light through yonder window breaks"

这样在每个位置 t · 模型都要预测 input[t+1]。一个 batch 同时学 256 个预测任务 · 训练效率远高于 RNN。

3 · Self-Attention · 从零推导 QKᵀ/√d

动机：为什么不用 RNN

RNN 把序列建模成 "隐状态滚动" · 第 t 步的 hidden 必须等第 t-1 步算完。串行 = 慢 · 而且远距离信息要经过 t 次衰减。 attention 的核心 idea 是 每个位置直接看其它所有位置一眼 · 一次并行算完。

三个矩阵：Q · K · V

对每个输入向量 x ∈ ℝᶜ · 我们用三个线性层把它映射到三个角色：

名字角色类比
Query (q)"我在找什么"搜索引擎里你输的关键词
Key (k)"我能匹配什么"网页的 title
Value (v)"我能给出什么内容"网页的正文

给 query q · 我们用它跟所有 key 算相似度 · 越像的拿越多对应 value：

\[ \text{Attention}(q, K, V) = \text{softmax}\!\left(\frac{q K^\top}{\sqrt{d_k}}\right) V \]

为什么要除以 √dₖ

这是面试高频题。简短答：防止 softmax 输入方差过大导致梯度消失。

推导

设 q · k 各分量独立 · 均值 0 · 方差 1。则 q · k = Σᵢ qᵢ kᵢ 共 dₖ 项。 方差 = dₖ × 1 = dₖ · 标准差 = √dₖ。

不除 · 当 dₖ=64 · qᵀk 量级 ~8 · softmax 接近 one-hot · 梯度几乎为 0。 除以 √dₖ 后 · 方差归一到 1 · softmax 仍在 "软" 区间 · 梯度健康。

从单 query 到 batch

实战中我们一次算 B 个序列 · 每个序列 T 个 query · 全用矩阵：

Q, K, V ∈ ℝ^(B, T, C)         # 三个 Linear 算出来
scores  = Q @ K.transpose(-2, -1) / sqrt(d_k)   # (B, T, T)
weights = softmax(scores + causal_mask)         # (B, T, T)
out     = weights @ V                            # (B, T, C)

两个矩乘 · 一个 softmax · 这就是 attention 的全部。

4 · Multi-Head · 为什么要切多个头

单头 attention 只能学一种 "怎么看" 的策略。multi-head 把 C 维隐空间切成 h 份 · 每份独立做 attention · 最后拼回来。

直觉

一个头可能学 "哪些字符常一起出现"（句法）· 另一个学 "哪些指代了同一个角色"（语义）· 又一个学 "押韵"。h 越大 · 模型能并行追踪的关系越多。

看 nano/gpt.py 里 CausalSelfAttention.forward()：

q = q.view(B, T, self.n_head, self.head_dim).transpose(1, 2)
k = k.view(B, T, self.n_head, self.head_dim).transpose(1, 2)
v = v.view(B, T, self.n_head, self.head_dim).transpose(1, 2)
# (B, n_head, T, head_dim) — h 个独立的 attention 在并行
y = F.scaled_dot_product_attention(q, k, v, is_causal=True)
y = y.transpose(1, 2).contiguous().view(B, T, C)  # 拼回 (B, T, C)

关键观察：multi-head 不增加参数量（C 维度还是 C）· 只是把同样的容量切片用。所以一般 head_dim 在 32-128 之间 · 太小学不到东西 · 太大不如开多头。

常见配置

模型n_layern_headn_embdhead_dim

GPT-2 small121276864
GPT-2 XL4825160064
Llama-2 7B32324096128
Llama-3 70B80648192128

注意 head_dim 长期稳定在 64 / 128 · 这不是巧合 · 是 GPU tile / FlashAttention 的硬件甜点。

5 · Causal Mask · 一行代码不偷看未来

语言模型必须保证：第 t 个 token 只能看 1..t · 不能看 t+1..T。否则训练时模型直接照抄 target · 推理时啥也不会。

实现：在 softmax 之前 · 把 attention scores 矩阵的上三角填成 -∞。softmax 之后这些位置的权重就是 0。

# 不用 SDPA 时手搓 mask
mask = torch.triu(torch.ones(T, T), diagonal=1).bool()  # 上三角 True
scores = scores.masked_fill(mask, float('-inf'))
weights = scores.softmax(dim=-1)

用 PyTorch ≥ 2.0 的 F.scaled_dot_product_attention(..., is_causal=True) · 这一切自动 · 而且会 fuse 成一个 kernel · MPS / CUDA 都加速。

坑

is_causal=True 只在 query/key 序列等长时正确。如果你做 cross-attention（encoder-decoder）· 必须显式传 attn_mask · 别图省事。

mask 的几何长相

T=4 · 1=可看 · 0=屏蔽

       k0 k1 k2 k3
   q0 [ 1  0  0  0 ]
   q1 [ 1  1  0  0 ]
   q2 [ 1  1  1  0 ]
   q3 [ 1  1  1  1 ]

下三角矩阵。第 t 行只有前 t+1 列是 1 · 严格不偷看未来。

6 · Position Embedding · 给序列一个时间感

attention 是 排列不变的。打乱 input 的顺序 · attention 输出会跟着乱 · 但注意力权重的相对结构不变。 所以你必须额外注入 "我在第几个位置" 的信号。

本书用的：learned absolute

最简单：开一个 nn.Embedding(block_size, n_embd) · 给每个 t ∈ [0, T) 学一个独立的向量 · 加到 token embedding 上：

pos = torch.arange(0, T, device=idx.device)   # (T,)
x = self.tok_emb(idx) + self.pos_emb(pos)     # (B, T, C)

简单 · 直观 · GPT-2 / GPT-3 都用这套。缺点：不能外推到训练时没见过的位置（你训了 256 · 推理塞 512 直接挂）。

更现代的：RoPE / ALiBi（phase 3 详讲）

方案核心哪些模型用
Learned Absolute每个 t 一个独立向量GPT-2 / GPT-3
Sinusoidal正弦周期 · 不用学原版 Transformer (2017)
RoPE把 q/k 旋转一个角度 · 跟 t 挂钩Llama / Qwen / Mistral
ALiBi在 attention scores 上加距离惩罚BLOOM · MPT

本 phase 用 learned · 够直观。phase 3 用 RoPE · 那时候你需要长上下文了。

7 · Pre-LN Block · GPT-2 后的标准结构

一个 transformer block = attention + MLP · 加 LayerNorm + 残差。LayerNorm 放哪里很关键。

位置结构谁用
Post-LNx = LN(x + Attn(x))原版 Transformer · 训深层不稳
Pre-LNx = x + Attn(LN(x))GPT-2 起所有人 · 深层稳定

本书用 Pre-LN：

def forward(self, x):
    x = x + self.attn(self.ln_1(x))   # 残差 + attention
    x = x + self.mlp(self.ln_2(x))    # 残差 + MLP
    return x

残差通道是 "无障碍" 的 (identity) · 梯度可以一路反传到底。LayerNorm 放在子模块前 · 子模块的输出再加回主线。这样把 LayerNorm 的非线性挡在残差通道之外 · 训练 100+ 层都不爆。

MLP 为什么放大 4×

nano/gpt.py 里 self.c_fc = Linear(C, 4*C) · 这是从原始 Transformer 论文 (2017) 起就定下的经验值。 直觉：attention 负责混合 token · MLP 负责非线性变换 hidden 维度。给 MLP 一个 4× 的隐空间 · 让它有地方做高维特征加工。 GPT / Llama / Qwen 全部 4× · 极少改。

参数量分布

一个 GPT block 的参数 ≈ 12 · C²（attention 4·C² · MLP 8·C²）。所以 MLP 占 2/3 · attention 才 1/3。 这就是 MoE / FFN 量化的发力点 · 后面 phase 5 / 9 详讲。

8 · Weight Tying · 一个被低估的 trick

nano/gpt.py 里有这一行：

self.lm_head.weight = self.tok_emb.weight

翻译成人话：输入的 token embedding 矩阵 和 输出的 lm_head 权重 共享同一份内存。

为什么这么干

好处说明
省参数少 vocab × n_embd 个参数 · GPT-2 small 直接省 38M（占总参 31%）
正则化强迫 input / output 用同一套语义空间 · 缓解过拟合
实测有效多个论文测 · ppl 略好 · 训练更稳

注意

tying 之后 · 优化器只更新 tok_emb.weight · lm_head 跟着变。如果你给两者分别设了不同的 weight_decay · 可能会出 bug。 AdamW 默认行为是合并梯度 · 一般没事 · 但 debug 时要警惕。

验证 tying 生效的最快方法（看 tests/test_nano_gpt.py）：

assert model.tok_emb.weight.data_ptr() == model.lm_head.weight.data_ptr()

9 · Training Loop · AdamW + cosine + warmup

AdamW vs SGD vs plain Adam

nano/train.py 用 torch.optim.AdamW。三大现代 LLM 用的全是这个 · 原因：

优化器问题判决
SGD + momentum对学习率超敏感 · 不能 ill-conditioned · LLM 训练根本不收敛×
plain Adamweight_decay 实现错了 · 实际是 L2 而不是 decoupled decay×
AdamWweight_decay 独立于梯度 · 跟学术理论一致✓ 全行业用

关键超参（nano/train.py 默认）：

lr        = 3e-4         # GPT-2 / nanoGPT 经验值
betas     = (0.9, 0.95)  # β₂ 砍到 0.95 是 GPT-3 论文的经验 · 长序列稳一些
weight_decay = 0.1       # GPT-3 / Llama 都用 0.1

Learning rate schedule

三段式：warmup → 巅峰 → cosine 衰减。看 nano/train.py 的 get_lr()：

if it < warmup_iters:
    return lr * (it + 1) / warmup_iters    # 线性 warmup
progress = (it - warmup_iters) / (max_iters - warmup_iters)
coeff = 0.5 * (1 + cos(π * progress))      # cosine decay
return min_lr + coeff * (lr - min_lr)

为什么 warmup

训练前几十步 · Adam 的二阶动量 v 还没估稳 · 直接给大 lr 容易让某些参数飞掉。 线性 warmup 给 v 一个 "暖身" 时间 · 然后再上巅峰 lr。GPT-3 用 375M token 的 warmup · 你 50 步够了。

Gradient clipping

torch.nn.utils.clip_grad_norm_(model.parameters(), 1.0) · 全局梯度 norm 裁到 1.0。 作用：偶尔出现 loss spike（比如训到一段噪声数据）时 · 防止一发回传炸掉参数。 LLM 训练几乎所有家都裁 · 默认 1.0。

调试 checklist · 训不动怎么办

  1. 第一步：把 lr 砍 10 倍。多数 "loss 爆炸" 是 lr 太大。
  2. 看 first step loss 是不是 ≈ ln(vocab_size)。莎士比亚 65 个字符 · ln 65 ≈ 4.17 · 我们实测 4.20 ✓。如果第一步就 100+ · 模型初始化挂了。
  3. 看 grad_norm。如果全 0 · forward 链断了。如果 nan · 数值溢出 · 检查混合精度。
  4. 关 dropout · 关 augmentation · 看能不能在一个 batch 上 overfit。能 → 数据有问题 · 不能 → 模型有问题。

10 · Sampling · temperature / top-k 的几何直觉

训完只能算 ppl 没意思 · 我们要让它说人话。看 nano/gpt.py 的 generate()：

logits = logits[:, -1, :] / max(temperature, 1e-8)   # (B, vocab)
if top_k is not None:
    v, _ = torch.topk(logits, top_k)
    logits[logits < v[:, [-1]]] = -inf
probs = F.softmax(logits, dim=-1)
idx_next = torch.multinomial(probs, num_samples=1)

Temperature

τ效果用途
0.1分布锐化 · 几乎贪心事实问答 · 代码补全
0.7-0.9合理多样对话 · 创作
1.0原 distribution无修改
1.5+变野 · 容易胡说brainstorming

τ 出现在 logits / τ 的位置 · τ 小 · logits 被放大 · softmax 输出更尖。τ → 0 时退化为 argmax（贪心采样）。

Top-k

把 logits 里 top-k 之外的全置 -∞ · 强制只在最高概率的 k 个 token 里采。 作用：禁止模型走 "极小概率但灾难性" 的路径（典型例子：聊天聊到一半突然出现日文乱码）。

常见组合：(temperature=0.8, top_k=40) 或 (temperature=0.9, top_p=0.92)（top-p 是 nucleus sampling · 这版没实现 · phase 4 加）。

几何视角

把 vocab 上的 distribution 想成一座山。temperature 控山的尖锐度 · top-k 控只在山顶 k 座峰里选。 两个旋钮一起调 · 你就能做出从严肃问答到自由创作的所有风格。

11 · macOS / MPS 适配的几个坑

本项目优先适配 Apple Silicon (M1/M2/M3) 的 MPS 后端 · 比 CPU 快 5-15 倍。但有几个老坑：

坑表现解
SDPA 在 MPS 早期不支持"NotImplementedError"升 PyTorch ≥ 2.2 · 本项目锁 2.12 ✓
fp16 不稳loss → nan用 fp32 或 bfloat16 (M2+)
大 batch OOM 没明显报错程序卡住或 hang从 batch_size=8 起涨 · 监控 Activity Monitor
多进程 dataloader 慢num_workers>0 反而变慢MPS 下用 num_workers=0
checkpoint 用 pickle 报错"weights_only" 警告本项目 sample.py 显式传 weights_only=False

device 选择代码

def pick_device():
    if torch.backends.mps.is_available():
        return torch.device("mps")
    if torch.cuda.is_available():
        return torch.device("cuda")
    return torch.device("cpu")

nano/train.py 自动选。在我的 M2 air 上 · 50 步 (toy) ~4 秒 · 5000 步 (default) ~10 分钟。
